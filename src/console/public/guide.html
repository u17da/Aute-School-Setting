1. 本ツールの全体概要と安全原則

本ツールは、まなびポケットの公式マニュアル 「9.2 学校設定」（p.197〜200） に記載されている11項目の設定について、対象校（最大約400校）の設定状態を自動検証し、安全に統一反映を行うための運用支援Webコンソールです。

① 対象学校
CSV選択・入力確認
→
② 現状調査
全校の現在値を自動収集
→
③ 設定・差分確認
目標設定 & 最終事前検証
→
④ 本番反映
安全な変更のみを本番適用

⑤ 実行結果
結果サマリ & レポート出力
🛡️ 事故を防ぐ5つの安全設計（Fail-Safe）
  • 現状調査ファースト（Discovery-First）: 設定値を決める前に、まず全校の「ありのままの現在値」を安全に読み取ります。いきなり本番反映されることは絶対にありません。
  • 二重Gateと最終事前検証: 設定を確定した後、本番反映直前に「最終事前検証（Final Preflight）」が100%成功しない限り、本番反映ボタンは物理的にロックされます。
  • 予約投稿削除リスクの自動保護: タイムラインやチャンネルを非表示にする（予約投稿が消去される）設定変更は、標準状態で自動的にスキップされ、現場の投稿データ誤消去を防ぎます。
  • 通信切断時の即時停止（Circuit Breaker）: 設定保存中に通信が途切れた場合、二重クリックによる事故を防ぐため自動的に処理を即時完全停止し、自動リトライを禁止します。
  • 世代不一致の自動検出（Fail-Closed）: サーバー再起動や更新が発生した場合、画面上に警告バナーを表示して反映ボタンを即時ロックし、不整合操作を防止します。

2. 【準備編】ツールの起動とCSV作成

コンソールの起動手順（自己完結Portable ZIP対応）

本ツールは 「自己完結型（Portable）」 として配布されています。会社PC側での Node.js のインストールや環境構築、コマンド入力は一切不要です。

1ZIPファイルを任意のフォルダへ展開（すべて展開）する

配布された Manapoke-School-Settings-vX.Y.Z-win-x64.zip を右クリックし、「すべて展開」を選択して任意のフォルダへ展開します。

2「Start-Manapoke.cmd」をダブルクリックする

展開先フォルダのルートにある Start-Manapoke.cmd をダブルクリックして起動します。

📁 フォルダ内の主要ファイル

・Start-Manapoke.cmd : ツールを起動します（自動でブラウザが開きます）
・Stop-Manapoke.cmd : ツールを安全に終了します
・はじめに.txt : かんたん操作手順書

起動チェックが自動実行された後、お使いの既定ブラウザで自動的に操作画面（http://127.0.0.1:3000）が開きます。

💡 既に起動している場合
Start-Manapoke.cmd を二重に実行した場合でも、二重起動は防止され、既存の操作画面がブラウザで前面に開きます。

学校一覧 CSV の作成仕様（Excel保存の注意点）

対象校の学校情報と管理者アカウントをまとめた CSV ファイルを1本用意します。

列名（ヘッダー） 必須 内容説明 記載例
schoolCode 必須 まなびポケットの学校コード（重複不可） SCH001
schoolName 必須 ログイン後に画面上の学校名と照合するための名称 ○○市立第一小学校
userId 必須 学校管理者のログインID admin_user01
password 必須 学校管理者のログインパスワード ••••••••
enabled 任意 処理対象とするか否か（true または false。空欄時は true） true
⚠️ Excel で保存する際の大事なお願い

Microsoft Excel で編集したファイルを保存する際は、ファイルの種類で必ず
「CSV UTF-8（コンマ区切り）（*.csv）」 を選択してください。
※ 通常の「CSV（コンマ区切り）」を選択すると、日本語の学校名が文字化けして照合エラーの原因となります。

3. 【STEP 1】対象学校の指定（画面1）

CSVの投入、学校数とアカウント情報の事前検証を行い、処理対象の学校群を確定させる最初のステップです。

1CSVファイルをドラッグ＆ドロップする

「CSVファイルをドラッグ＆ドロップ、またはここをクリックして選択」の枠内に、準備した CSV ファイルを入れます。

📁 読み込み後の表示例

選択ファイル: schools.csv (227 B)

読み込み結果: 全 3 校（有効: 3 校）

#学校コード学校名ログイン情報
1SCH001テスト第一小学校設定済 (非表示)
2SCH002テスト第二中学校設定済 (非表示)

「学校一覧プレビュー」に学校が表示され、ログイン情報が「設定済 (非表示)」となっていることを確認します。
※ セキュリティ保護のため、パスワード等の秘密情報はブラウザ画面やログに一切露出しません。

2対象学校を確定し、現状調査へ進む

有効学校数を確認後、青色の [対象学校を確定して現状調査へ進む] ボタンをクリックします。
対象学校のスナップショットが確定され、自動的に「2. 現状調査」タブへ移動します。

4. 【STEP 2】現状調査の実行（画面2）

自動化ブラウザが対象校の管理画面へ順番にログインし、各校の「ありのままの現在設定値」を安全に読み取ります（この段階では書き込みは一切行われません）。

1「現状調査を開始する」をクリックする

青色の [現状調査を開始する（読み取りのみ）] ボタンをクリックすると、調査バッチが起動します。

進行状況の見方

指標名 表示内容と目安
進捗バー / カウント 全体の進行率（％）と、完了した学校数（例: 150 / 400 校）です。
読み取り成功 ログインと11項目の読み取りが完了した学校数です（緑色）。
読み取り失敗 パスワード相違や通信タイムアウト等で失敗した学校数です（赤色）。
残りの学校数 これから読み取りを行う学校の数です。
完了予定までの時間 直前の読み取り速度をもとに推計した、全校完了までの残り時間です。
🛑 途中で処理を止めたい場合（安全中断）

業務終了時間やネットワークトラブル等で処理を中断したい場合は、赤色の [安全に中断・停止する] ボタンを押してください。
現在処理中の1校が完了した直後に安全に停止し、中断状態として自動保存されます。後から [中断箇所から再開する] や [失敗した学校のみ再読み取りする] で安全に続きを実行できます。

🚀 全校の読み取りが完了すると

読み取り成功率が 100% に達すると、画面上部の [3. 設定・差分確認] タブがアンロックされ、目標設定の検討に進むことができます。

5. 【STEP 3】設定・差分確認（画面3）

現状調査で収集した各校の現在値をベースに、一括変更したい目標設定を指定し、ブラウザ再アクセスなしで即時に差分・影響範囲を確認するステップです。

1目標設定を指定する（Profile Editor）

画面上部の「一括変更する設定項目の指定」テーブルで、11項目の設定値をプルダウンで指定します。

便利ボタンの活用

デフォルトを一括設定 : まなびポケット推奨の一般的な設定値をまとめて自動セットします。
全項目を変更しない : 全項目を「UNMANAGED (変更しない)」にし、全校の現在値をそのまま維持します。

  • 設定値（ON / OFF / 利用する / 利用しない等）を指定した場合: 全校をその設定値に統一変更する計画を立てます。
  • 「UNMANAGED (変更しない)」を指定した場合: その項目は触らず、各学校の現在の設定をそのまま引き継ぎます。
2差分プレビューを即時確認する

設定値を変更すると、下部の「設定差分プレビュー」が瞬時に再計算されます：

  • 変更対象校数: 設定値が変更される学校の総数
  • 変更なし校数: 現在の設定がすでに目標値と一致している学校数
  • 予約投稿削除リスク校数: タイムラインやチャンネルをOFFにするため投稿消去リスクがある学校数
  • 契約外機能の警告: 「心の健康観察」など、その学校で契約がなく画面上に存在しない項目を有効化しようとした場合の警告
3設定を確定し、最終事前検証（Final Preflight）を実行する

設定内容に問題がなければ、青色の [この設定内容を確定する] ボタンを押します。
設定が確定（Profile Snapshot生成）された後、[最終事前検証を開始する（Final Preflight）] をクリックします。

🔒 最終事前検証の二重ロック

確定した設定内容で全校への書き込み計画が100%成立するかを、事前に検証します。この最終事前検証が正常完了（有効期限内）して初めて、本番反映の実行が可能になります。

6. 【STEP 4】設定の反映・適用（画面4）

最終事前検証の結果に基づき、対象学校へ実際に設定の書き込み（本番反映）を行うステップです。

1反映準備（Prepare Apply）を行う

青色の [本番反映の準備を行う（安全チェック）] ボタンをクリックします。
システムが Global Gate を検証し、破壊的変更（予約投稿消去リスク）の学校を自動的に除外（安全スキップ）した上で、安全な学校のみを対象とする Manifest を生成し、1回限りの確認トークンを発行します。

2最終確認モーダルで内容を承認し、本番反映を開始する

表示される最終確認モーダルで、反映対象校数およびスキップ校数を確認します。
「上記の内容を確認しました」チェックボックスにチェックを入れると、赤色の [本番反映を開始する] ボタンが有効になります。

🔒 二重実行防止と通信遮断保護
  • 二重実行防止（Single-Flight Guard）: ボタンの連打や同時リクエストはサーバー側で物理的に拒絶されます。
  • 通信切断時の安全停止: 設定保存ボタン押下直後にネットワークが途切れた場合、二重クリック事故を防ぐため自動的に即時停止します。

7. 【STEP 5】実行結果とレポート出力（画面5）

本番反映が完了すると、自動的に「5. 実行結果」画面へ切り替わります。
サーバーから受け取った確実な実行結果実績が表示され、監査・エビデンス用のレポートファイルをダウンロードできます。

実行結果の実績サマリ（6分類）

各学校の実行結果は、以下の6つのカテゴリに厳密に分類されて表示されます：

分類名 ステータス 内容説明
反映成功 APPLIED 設定値の変更・保存・再検証がすべて正常に完了した学校です。
変更なし ALREADY_CONFIGURED すでに目標通りの設定になっていたため、不要な書き込みを行わず正常完了した学校です。
安全スキップ SKIPPED 予約投稿削除リスク等があるため、事故防止ポリシーに基づき自動除外された学校です。
反映ブロック BLOCKED 設定矛盾や契約不一致等により、事前検証時点でブロックされた学校です。
失敗 FAILED 通信タイムアウトやログイン失敗等で正常に保存できなかった学校です。
未処理 NOT_PROCESSED 安全停止や中断により、処理が到達しなかった残りの学校です。

レポート・エビデンスのダウンロード

画面下部のダウンロードエリアから、監査提出用のレポート（JSON）をダウンロードできます：

  • 📄 本番集計レポート（Production Summary）: 今回の本番反映の全校実績・変更前後値・実行時間を記録した公式サマリです。
  • 📋 最終事前検証レポート（Final Preflight Report）: 本番反映直前の検証結果とハッシュ整合性のエビデンスです。
  • 🔍 現状調査スナップショット（Observation Snapshot）: 設定変更前に収集した全校の初期状態データです。
  • 💾 チェックポイント（Checkpoint）: 途中の実行進捗と各校詳細を記録した復旧用データです。
🗑️ 過去データのリセットについて

画面右上の [🗑️ 実行結果をリセット] ボタンを押すと、過去の実行記録やチェックポイントを退避（archive）し、初期状態に戻すことができます。別の案件や新しいCSVで最初から作業を開始する際にご利用ください。

8. トラブルシューティング & よくある質問 (FAQ)

Q1. 画面1で「対象学校を確定する」ボタンが押せません。

チェックリスト
  1. CSVファイルは選択されていますか？ → ドロップゾーンにファイルを入れてください。
  2. CSVのヘッダー名は正しいですか？ → schoolCode,schoolName,userId,password が含まれているか確認してください。
  3. Excel保存形式は正しいですか？ → 「CSV UTF-8（コンマ区切り）（*.csv）」で保存されているか確認してください。

Q2. 画面上部に「サーバーの再起動またはバージョン更新が検出されました」と黄色いバナーが出ました。

サーバープロセスが再起動したか、新しいバージョンのプログラムが配置されたことを検知しました。
古い画面のまま操作を続けると不整合事故（旧画面＋新サーバー）を起こす危険があるため、安全装置（Fail-Closed）が働き、本番反映ボタンが一時ロックされています。
バナー右側の [画面を再読み込み] ボタン（またはブラウザのF5キー）を押して画面を更新してください。

Q3. 「設定・差分確認」で設定の不整合警告が出ます。

「タイムライン・チャンネル機能」をOFFに設定している状態で、子機能（全体チャンネル・保護者チャンネル）をONにしようとすると発生します。
親機能をONにするか、子機能を「OFF」または「変更しない」に合わせてください。

Q4. 最初からすべてやり直したいです。

画面右上にある赤字の [🗑️ 実行結果をリセット] ボタンを押してください。確認ダイアログで「OK」を押すと、過去の実行記録が安全にアーカイブされ、STEP 1 の初期状態に戻すことができます。

9. ステータスコード・エラー用語早見表

ログや失敗校一覧に表示される主要なコードの意味と、オペレーターの対応手順です。

コード名 状態 意味とオペレーターが取るべき対応
SUCCESS 正常完了 設定変更・保存・検証がすべて正常に完了しました。
SUCCESS_ALREADY_CONFIGURED 変更なし 現在の設定がすでに目標値と一致しているため、変更を行わずにスキップしました。
SKIPPED_DESTRUCTIVE 安全スキップ 予約投稿削除リスクがあるため、事故防止のため書き込みを自動除外しました。
NOT_PROCESSED 未処理 安全停止や中断により、処理が到達しなかった学校です。
PREFLIGHT_STATE_CHANGED 安全スキップ 事前検証の後に、学校側で手動変更された形跡を検知したため、上書き防止でスキップしました。
SAVE_OUTCOME_UNKNOWN 重大エラー 保存ボタン押下直後に通信が切れ、成否が判定できません。二重事故防止のため即時停止しました。手動で管理画面をご確認ください。
INTERRUPTED 中断 「安全に中断・停止する」を押したことによる意図的な中断です。「中断箇所から再開する」で続きを実行できます。
LOGIN_FAILED エラー ログインに失敗しました。CSVの userId または password をご確認ください。
CONTRACT_NOT_AVAILABLE 警告 その学校で未契約の機能です。設定項目を「変更しない」に戻すことを推奨します。
