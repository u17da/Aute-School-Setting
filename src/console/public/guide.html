1. 本ツールの全体概要と安全原則

本ツールは、まなびポケットの公式マニュアル 「9.2 学校設定」（p.197〜200） に記載されている11項目の設定について、対象校（最大約400校）の設定状態を自動検証し、安全に統一反映を行うための運用支援Webコンソールです。

① 設定と事前検証
CSV選択・設定指定・入力チェック
→
② 検証の進行状況
全校の現在値を自動読み取り
→
③ 検証結果
差分・削除リスク・契約外の確認
→
④ 設定の反映・適用
安全な変更のみを本番反映
🛡️ 事故を防ぐ4つの安全設計（Fail-Safe）
  • 二段階実行モデル: 事前検証（読み取りのみ）を全校100%成功させない限り、設定の反映（書き込み）は物理的にロックされます。いきなり本番反映されることは絶対にありません。
  • 予約投稿削除リスクの自動保護: タイムラインやチャンネルを非表示にする（予約投稿が消去される）設定変更は、標準状態で自動的にスキップされ、誤消去を防ぎます。
  • ログイン情報の完全保護: CSV内の学校管理者パスワードは、PCのメモリ上でのみ厳重に扱われ、画面表示・ログ・レポートファイルには一切残りません。
  • 通信遮断時の自動停止: 設定保存中に通信が途切れた場合、二重クリックによる事故を防ぐため自動的に処理を即時停止（Circuit Breaker）し、自動リトライを禁止します。

2. 【準備編】ツールの起動とCSV作成

コンソールの起動手順（自己完結Portable ZIP対応）

本ツールは 「自己完結型（Portable）」 として配布されています。会社PC側での Node.js のインストールや環境構築、コマンド入力は一切不要です。

1ZIPファイルを任意のフォルダへ展開（すべて展開）する

配布された Manapoke-School-Settings-vX.Y.Z-win-x64.zip を右クリックし、「すべて展開」を選択して任意のフォルダへ展開します。

2「Start-Manapoke.cmd」をダブルクリックする

展開先フォルダのルートにある Start-Manapoke.cmd をダブルクリックして起動します。

📁 フォルダ内の主要ファイル

・Start-Manapoke.cmd : ツールを起動します（自動でブラウザが開きます）
・Stop-Manapoke.cmd : ツールを安全に終了します
・はじめに.txt : かんたん操作手順書

起動チェックが自動実行された後、お使いの既定ブラウザで自動的に操作画面（http://127.0.0.1:3000）が開きます。

💡 既に起動している場合
Start-Manapoke.cmd を二重に実行した場合でも、二重起動は防止され、既存の操作画面がブラウザで前面に開きます。
ℹ️ 開発環境で起動する場合
開発PCのソースコードから直接起動する場合は、ターミナルで npm run console を実行することでも起動可能です。

学校一覧 CSV の作成仕様（Excel保存の注意点）

対象校の学校情報と管理者アカウントをまとめた CSV ファイルを1本用意します。

列名（ヘッダー） 必須 内容説明 記載例
schoolCode 必須 まなびポケットの学校コード（重複不可） SCH001
schoolName 必須 ログイン後に画面上の学校名と照合するための名称 ○○市立第一小学校
userId 必須 学校管理者のログインID admin_user01
password 必須 学校管理者のログインパスワード ••••••••
enabled 任意 処理対象とするか否か（true または false。空欄時は true） true
⚠️ Excel で保存する際の大事なお願い

Microsoft Excel で編集したファイルを保存する際は、ファイルの種類で必ず
「CSV UTF-8（コンマ区切り）（*.csv）」 を選択してください。
※ 通常の「CSV（コンマ区切り）」を選択すると、日本語の学校名が文字化けして照合エラーの原因となります。

3. 【STEP 1】設定と事前検証（画面1）

CSVの投入、一括変更したい設定内容の指定、および入力チェックを行う最初のステップです。

1CSVファイルをドラッグ＆ドロップする

「CSVファイルをドラッグ＆ドロップ、またはここをクリックして選択」の枠内に、準備した CSV ファイルを入れます。

📁 読み込み後の表示例

選択ファイル: schools.csv (227 B)

読み込み結果: 合計 3 校 (有効: 3 校, 無効: 0 校)

#学校コード学校名ログイン情報
1SCH001テスト第一小学校設定済 (非表示)
2SCH002テスト第二中学校設定済 (非表示)

「学校一覧プレビュー」に学校が表示され、ログイン情報が「設定済 (非表示)」となっていることを確認します。また、「有効学校数」が予定している校数と合っているか確認してください。

2一括変更する設定項目を指定する（Profile Editor）

画面下部の「一括変更する設定項目の指定」テーブルで、11項目の設定値をプルダウンで指定します。

便利ボタンの活用

デフォルトを一括設定 : まなびポケット推奨の一般的な設定値をまとめて自動セットします。
全項目を変更しない : 全項目を「UNMANAGED (変更しない)」にし、全校の現在値をそのまま維持します。

  • 設定値（例: ON / OFF / 利用する / 利用しない等）を指定した場合: 全校をその設定値に統一変更する計画を立てます。
  • 「UNMANAGED (変更しない)」を指定した場合: その項目は触らず、各学校の現在の設定をそのまま引き継ぎます。
3親機能・子機能の不整合警告が出ていないか確認する

まなびポケットの仕様上、「タイムライン・チャンネル機能」がOFF の状態で、子機能である「全体チャンネル」や「保護者チャンネル」を ON にすることはできません。

⚠️ 設定の不整合警告が出た場合の対処法

赤色の警告「『タイムライン・チャンネル機能』がOFFの場合、子機能をONに設定することはできません」が表示された場合は、親機能を ON にするか、子機能を OFF または「変更しない」に合わせてください。不整合が解消されるまで事前検証は開始できません。

4「事前検証を開始する」ボタンをクリックする

画面最下部の青色ボタン [事前検証を開始する（読み取りのみ・変更なし）] をクリックします。
※ 設定値に不整合がある場合はボタンが無効化（薄い色）されています。
クリックすると自動的に「2. 検証の進行状況」画面へ切り替わり、各校の設定読み取りが始まります。

4. 【STEP 2】検証の進行状況（画面2）

自動化ブラウザが対象校の管理画面へ順番にログインし、現在の設定値を安全に読み取ります（この段階では書き込みは一切行われません）。

進行状況の見方

指標名 表示内容と目安
進捗バー / カウント 全体の進行率（％）と、完了した学校数（例: 150 / 400 校）です。
読み取り完了 (正常) ログインと11項目の読み取りが完了した学校数です（緑色）。
エラー発生 (失敗) パスワード相違や通信タイムアウト等で失敗した学校数です（赤色）。
残りの学校数 これから読み取りを行う学校の数です。
完了予定までの時間 直前の読み取り速度をもとに推計した、全校完了までの残り時間です。
🛑 途中で処理を止めたい場合（安全中断）

業務終了時間やネットワークトラブル等で処理を中断したい場合は、赤色の [安全に中断・停止する] ボタンを押してください。
現在処理中の1校が完了した直後に安全に停止し、中断状態として自動保存されます。後から中断箇所から続きを再開できますので、強制終了等は行わないでください。

5. 【STEP 3】検証結果の確認（画面3）

全校の事前検証が完了すると、自動的に「3. 検証結果」画面へ切り替わります。
ここでは、現状の設定分布や、設定変更に伴うリスクの有無を確認します。

集計結果の読み解き方

画面は上から順に、分かりやすく整理されて表示されます：

集計指標の構成

最上段: 対象学校数（全校） … 今回投入された学校の総数（例: 400校）

① 読み取り結果の内訳
・読み取り成功（正常）
・読み取り失敗（エラー）
② 反映判定の内訳
・安全に反映可能（変更あり・リスクなし）
・反映ブロック（注意が必要な学校）
・予約投稿削除リスクの学校（投稿消去リスクあり）

重要な警告アラートの確認

  • ⚠️ 予約投稿削除リスクの学校（DESTRUCTIVE_CHANGE_RISK）:
    設定変更を行うと、すでに教員が設定した未来の予約投稿が消えてしまうリスクがある学校の一覧です。
  • ⚠️ 契約外機能の有効化警告（CONTRACT_NOT_AVAILABLE）:
    「心の健康観察」など、その学校で契約がなく画面上に存在しない項目を有効化しようとした学校の一覧です（設定項目を「変更しない」に戻すことを推奨します）。

現在の設定値と変更予定の内訳（11項目統合テーブル）

11項目それぞれについて、「現在の各校の設定状況」 と 「適用後にどの設定に変わるか（内訳校数）」 が1つの表で確認できます。
例: 「現在すでにONの学校: 350校 / 変更なし」「現在OFFの学校: 50校 / OFF→ONへ変更」など、影響範囲が一目で分かります。

失敗校への対応とやり直しボタンの使い分け

画面右上のボタン 動作内容と使用場面
[中断箇所から再開する] 途中で「安全に中断・停止」した場合や、未着手の学校がある場合に、続きから処理を再開します。
[失敗した学校のみ再読み取りする] 通信エラー等で読み取り失敗（エラー）となった学校のみを対象に、再度読み取りを行います。
[🗑️ 実行結果をリセット] 新機能: 過去の実行結果やチェックポイントを完全に初期化し、最初からやり直したい場合に使用します（確認ダイアログが表示されます）。
🚀 「4. 設定の反映・適用」タブへの進み方

読み取り成功率が 100% に達すると、画面上部のナビゲーションバーにある [4. 設定の反映・適用] タブがアンロックされ、クリックできるようになります。

6. 【STEP 4】設定の反映・適用（画面4）

事前検証の結果に基づき、対象学校へ実際に設定の書き込み（本番反映）を行う最終ステップです。

1反映前チェック状態を確認する

画面上部の「反映前チェック状態: 正常（書き込み可能）」が表示されていることを確認します。
※ 設定ファイルの変更や有効期限切れ（24時間経過）がある場合は警告が表示され、事前検証のやり直しが求められます。

2予約投稿削除リスクの取り扱いを選択する

タイムラインやチャンネルをOFFにする学校（予約投稿が消去される学校）の取り扱いを決めます：

※ チェックOFF（標準推奨）: 予約投稿削除リスクのある学校は自動的にスキップされ、安全な学校のみに反映されます。
※ チェックON: 学校現場と事前合意が取れており、消去を承諾した上で全校に反映させたい場合のみチェックを入れます。

3「反映内容を確認する」をクリックし、最終承認を行う

青色の [反映内容を確認する] ボタンを押すと、最終確認モーダル画面が表示されます。

⚠️ 設定反映の最終確認モーダル

反映対象校: ○○ 校 ／ スキップ校: ○○ 校

モーダル内の対象校数を確認し、同意チェックボックスにチェックを入れると、赤色の [設定変更を本番反映する] ボタンが押せるようになります。

4反映の進行状況を見守る

反映が始まると、ブラウザが各校にログインし、設定変更・保存・保存後の再検証を1校ずつ安全に実行します。
進行バーと実行ログで進行状況をリアルタイムに確認できます。

🔒 万が一の通信遮断時の安全保護

「保存する」ボタンを押した直後にネットワークが切断される等のトラブルが起きた場合、本ツールは二重クリック事故を防ぐため直ちに全体の処理を自動停止します。自動再試行は行われませんので、該当校の状況を管理画面でご確認ください。

7. トラブルシューティング & よくある質問 (FAQ)

Q1. 画面1で「事前検証を開始する」ボタンが押せません（色が薄い）。

チェックリスト
  1. CSVファイルは選択されていますか？ → ドロップゾーンにファイルを入れてください。
  2. 「設定の不整合」警告が出ていませんか？ → タイムライン機能がOFFなのに、子機能（全体/保護者チャンネル）がONになっていると開始できません。設定を揃えてください。
  3. ログイン情報の「未設定・不足」がありませんか？ → CSV内のIDやパスワードが空欄の学校がないか確認してください。

Q2. 一部の学校で「予約投稿削除リスク」の警告が出ました。どうすればよいですか？

タイムラインや全体チャンネルを非表示にする設定が含まれているためです。
そのまま「4. 設定の反映・適用」に進むと、その学校は自動的にスキップ（変更されない）されますので安全です。もし反映させたい場合は、学校現場に予約投稿がないことを確認した上で、画面4の許可チェックボックスにチェックを入れてください。

Q3. 最初からすべてやり直したいです。

画面3（検証結果）の右上にある赤字の [🗑️ 実行結果をリセット] ボタンを押してください。確認ダイアログで「OK」を押すと、過去の実行記録がクリアされ、初期状態に戻すことができます。

Q4. 画面4で「反映内容を確認する」ボタンが押せません。

事前検証でエラーとなった学校（読み取り失敗校）が残っている可能性があります。
画面3の「失敗した学校のみ再読み取りする」を実行し、成功率を 100% にしてください。

8. ステータスコード・エラー用語早見表

ログや失敗校一覧に表示される主要なコードの意味と、オペレーターの対応手順です。

コード名 状態 意味とオペレーターが取るべき対応
SUCCESS 正常完了 設定変更・保存・検証がすべて正常に完了しました。
SUCCESS_ALREADY_CONFIGURED 変更なし 現在の設定がすでに目標値と一致しているため、変更を行わずにスキップしました。
SKIPPED_DESTRUCTIVE 安全スキップ 予約投稿削除リスクがあるため、事故防止のため書き込みをスキップしました。
PREFLIGHT_STATE_CHANGED 安全スキップ 事前検証の後に、学校側で手動変更された形跡を検知したため、上書き防止でスキップしました。
SAVE_OUTCOME_UNKNOWN 重大エラー 保存ボタン押下直後に通信が切れ、成否が判定できません。二重事故防止のため即時停止しました。手動で管理画面をご確認ください。
INTERRUPTED 中断 「安全に中断・停止する」を押したことによる意図的な中断です。「中断箇所から再開する」で続きを実行できます。
LOGIN_FAILED エラー ログインに失敗しました。CSVの userId または password をご確認ください。
CONTRACT_NOT_AVAILABLE 警告 その学校で未契約の機能です。設定項目を「変更しない」に戻すことを推奨します。
