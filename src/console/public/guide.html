1. 本ツールの概要と全体ワークフロー

本ツール（Operator Console）は、まなびポケット操作マニュアル 「9.2 学校設定」（p.197〜200） に記載されている11項目の設定について、対象校（最大約400校）の設定状態を自動検証し、安全に統一適用を行うためのローカル専用運用支援コンソールです。

① 設定と事前検証
CSV投入・設定指定・入力チェック
→
② 検証の進行状況
全校の現在値を安全に読取 (保存なし)
→
③ 検証結果と内訳
差分・破壊的変更・未契約の確認
→
④ 設定の反映・適用
非破壊変更のみを安全に本番適用
🛡️ 事故を未然に防ぐ多重安全原則（Fail-Safe by Default）

本ツールは、運用オペレーターが誤った操作を行っても事故が発生しないよう、以下の強固な安全防護を標準装備しています：

  • 二段階実行モデル: 事前読み取り（Preflight）を100%完了させない限り、本番書き込み（Production Apply）は物理的にアンロックされません。
  • 破壊的変更の自動除外（マニフェスト制約）: 「予約投稿削除リスク」を伴う学校は本番適用時に自動的にスキップされ、安全な非破壊変更のみが適用されます。
  • 秘密情報の完全非露出: パスワード等の認証情報はメモリ上でのみ安全に保持され、画面・ログ・レポートJSON・ブラウザ通信には一切表示・記録されません。
  • 故障時の自動停止（SAVE_OUTCOME_UNKNOWN 保護）: 保存処理後に通信遮断等が発生した場合、二重書き込み事故を防止するため即時停止し、自動再試行を禁止します。

2. 事前準備と起動方法 (Excel CSV作成)

コンソールの起動手順

1PowerShell を開き、コマンドを実行する

プロジェクトフォルダで以下のコマンドを実行します：

npm run console
2ブラウザで画面を開く

ブラウザ（Chrome, Edge等）を開き、次のURLにアクセスします。
http://localhost:3000

💡 ローカルホスト専用バインド
外部ネットワークからのアクセスはセキュリティ上遮断されており、あなたのPC（127.0.0.1）からのみ操作可能です。

学校一覧 CSV の作成方法（Excel対応）

学校情報と学校管理者ログイン情報を1本にまとめた CSV ファイルを準備します。

カラム名（ヘッダー） 必須 内容説明 例
schoolCode 必須 まなびポケットの学校コード（重複不可） 13101001
schoolName 必須 画面上の学校名と照合するための正確な名称 千代田区立第一小学校
userId 必須 学校管理者のログインID admin_school01
password 必須 学校管理者のログインパスワード ••••••••
enabled 任意 処理対象とするか否か（true または false。空欄時は true） true
⚠️ Excel で CSV を保存するときの重要ポイント

Microsoft Excel で編集したファイルを保存する際は、必ず「名前を付けて保存」でファイルの種類を
「CSV UTF-8（コンマ区切り）（*.csv）」 に指定してください。
※ 通常の「CSV（コンマ区切り）」を選択すると、日本語の学校名が文字化け（Shift_JIS化）する原因となります。

3. 画面1: Setup & Validation (設定エディタと検証)

実行対象校の投入、適用予定設定の編集・確認、および静的検証を行う初期画面です。

操作手順

1CSV ファイルをアップロードする

点線枠（ドロップゾーン）に CSV ファイルをドラッグ＆ドロップするか、枠内をクリックしてファイルを選択します。
アップロード後、直ちに「学校リスト Preview」に先頭最大20校が表示されます。パスワードは自動でマスクされ「設定済 (非表示)」と表示されます。

2想定有効学校数（Safety Gate）を入力する

「想定有効学校数 (Safety Gate)」欄に、今回処理することを予定している学校数（例: 3 や 400）を半角数字で入力します。
CSV内の有効学校数と一致するとバッジが緑色（一致）に変化します。誤投入や行抜けを防止するため、不一致時は後続の処理が物理的にブロックされます。

3Profile Editor で適用設定を調整する（新機能）

画面中央の「適用プロファイル設定 (Profile Editor)」テーブルで、11項目の設定値を直接指定できます。

Profile Editor の便利機能
推奨設定 : 一般的な教育現場の運用標準設定を一括反映 全項目維持 : 全項目を「UNMANAGED (変更なし)」に設定 JSON インポート : 保存済みの設定プロファイル（.json）を読込 JSON エクスポート : 編集した設定をローカルPCへ保存

※ ドロップダウンで「UNMANAGED (変更なし)」を選択した項目は、各学校の現在の設定値がそのまま維持されます。

⚠️ 破壊的変更リスクのリアルタイム警告バナー

設定編集中に「予約投稿削除リスク」を伴う設定（例: タイムライン機能 → OFF や 全体チャンネル → OFF）を選択すると、即座に黄色のアラートバナーが出現し、どの項目がリスク要因であるかが明示されます。

4「入力を検証」→「Read-only Preflight を実行」

青色の [入力を検証 (--validate-only)] をクリックします。数秒で構文・認証解決・ハッシュが検証されます。
検証に PASS すると、緑色の [Read-only Preflight を実行] がアンロックされます。クリックすると画面2（進捗監視）へ切り替わり、全校の事前読み取りが始まります。

4. 画面2: Preflight Progress (進捗監視と安全停止)

全校のまなびポケットに順次アクセスし、現在の設定値を安全に読み取ります（この段階では書き込みは一切行われません）。

画面の見方（5大メトリクス）

指標名 表示内容と確認のポイント
進捗バー / カウント 全体の進捗パーセンテージと完了校数（例: 150 / 400 (37.5%)）を表示します。
Success (正常) 設定の読み取りが正常に完了した学校数です（緑色）。
Failed (エラー) 認証相違やタイムアウト等で読み取りに失敗した学校数です（赤色）。
Remaining (残り) これから処理を行う未着手校数です。
Elapsed / ETA 開始からの経過時間と、全校完了までの推定残り時間です。
🛑 途中で処理を中断したい場合（Graceful Shutdown）

処理を中断したい場合は、赤色の [安全に停止 (Graceful Shutdown)] をクリックしてください。
現在処理中の1校が完了した時点で安全に停止し、状態が「中断（INTERRUPTED）」として保存されます（後から続きを簡単に再開できます）。

5. 画面3: Results & Distribution (結果分析とリスク判定)

Preflight 完了後、全校の現在値と適用予定値の差分、および安全性が集計表示されます。

重要な警告アラートの確認

  • ⚠️ 予約投稿削除リスク警告 (DESTRUCTIVE_CHANGE_RISK):
    設定変更に伴い予約投稿が消去されるリスクのある学校が一覧表示されます（本番適用時に自動スキップされます）。
  • ⚠️ 未契約機能の有効化要求警告 (CONTRACT_NOT_AVAILABLE):
    「心の健康観察」など、その学校で契約がなく画面上に存在しない項目を有効化しようとした学校の一覧です。
  • ⚠️ RESULTS_STALE 警告:
    表示中のデータが古いCSV/プロファイルの結果である場合に表示されます。再検証・再Preflightを行ってください。

8大総合集計指標の読み解き方

集計項目 意味とオペレーターの判断基準
対象学校 (Total) 投入された全学校数。
読取成功 (Success) 設定を取得できた学校数（全体の100%であることが必須）。
設定変更なし (0件) 現状がすでに目標値と一致しており、変更の必要がない学校数（安全維持）。
設定変更予定 (>0件) 今後設定変更が必要となる学校数。
計画ブロック (Blocked) 依存関係の不整合等で適用できない学校数。
破壊的変更校 (Destructive) 予約投稿削除リスクがあるため本番適用で自動スキップされる学校数。
安全書込可能 (Write Eligible) 安全に非破壊変更を適用できる対象校数。
🚀 「4. Production Apply」タブへの移行条件

全校の読取が100%成功し、Preflight が正常完了（COMPLETE）すると、画面上部ナビゲーションの [4. Production Apply] タブが自動的にアンロックされ、クリックできるようになります。

6. 画面4: Production Apply (非破壊本番適用 v1)

事前検証（Preflight）の結果をもとに、安全な非破壊変更のみを本番環境へ書き込む機能です。

① Global Gate（全体前提条件）の自動検証

画面上部の「Global Gate 状態」カードを確認します。以下の条件がすべて満たされている場合のみ適用準備へ進めます：

  • Preflight が全校成功（読取成功率 100%）で完了していること
  • Preflight 完了から有効期限（24時間）以内であること
  • Preflight 実行時と現在の設定プロファイル（profileHash）および学校一覧（schoolsHash）が完全に同一であること

② 適用計画マニフェスト (Target Manifest) の自動制約

システムは Preflight 結果を解析し、以下の3群に全校を自動分類します：

マニフェストによる自動分類（安全ガード）
分類対象校の扱い安全性
本番適用対象 (Non-destructive) ブラウザが自動アクセスし、設定変更＆保存を実行 安全 破壊的リスクなし
破壊的変更スキップ (Skipped) 書き込みを行わず自動スキップ（SKIPPED_DESTRUCTIVE） 完全保護 投稿消去を防止
設定変更不要校 (Already Configured) 変更の必要がないためスキップ（SUCCESS_ALREADY_CONFIGURED） 維持 現状維持

③ 本番適用の実行手順（二段階確認モーダル）

1「本番適用を確認する (Prepare)」をクリック

青色の [本番適用を確認する (Prepare)] ボタンを押すと、最終確認モーダルが表示されます。

2確認モーダルで対象数を確認し、チェックを入れる

モーダル内に表示される「適用対象校数」「スキップ校数」「ハッシュ値」を目視確認します。
確認後、「上記の適用対象校数および非破壊設定変更の内容を確認しました」 のチェックボックスをクリックしてチェックを入れます。

3「非破壊変更を本番適用する」をクリック

赤色の [非破壊変更を本番適用する] ボタンが活性化します。クリックすると本番書き込み処理が開始されます。

④ リアルタイム適用進捗監視と安全停止

画面下部に「本番適用 進行状況」が表示され、1校ずつ安全に変更・保存・更新後検証が行われます。
途中で止めたい場合は、[安全に停止 (Graceful Shutdown)] ボタンで安全に中断できます。

🔒 万が一の通信遮断時の安全保護 (SAVE_OUTCOME_UNKNOWN)

設定変更の「更新する」ボタンを押した直後にネットワークが切断されるなど、保存が成功したか失敗したか判定できない事態が発生した場合、本ツールは二重クリックによる事故を防ぐため直ちにバッチ全体を自動停止（Circuit Breaker発動）します。
自動再試行は物理的に行われませんので、該当校の状況を目視確認してください。

7. 読取失敗・中断時の再開と再試行

画面右上アクションボタンの使い分け

ボタン 動作内容と使用する場面
[Preflight を再開 (--resume)] 途中で安全停止した場合（中断校 INTERRUPTED）や未処理校（PENDING）を1回の操作で続きから自動再開します。
正常完了した学校はスキップされるため二重実行の心配はありません。
[失敗校のみ再読取 (--retry-failed)] 一時的な通信エラー等で読み取り失敗（FAILED）となった学校のみを対象に再実行します。

8. トラブルシューティング & よくある質問 (FAQ)

Q1. 「本番適用を確認する (Prepare)」ボタンが押せません。

確認ポイント
  1. Preflight は100%成功していますか？ → 読取失敗（Failed）が1校でもあると本番適用はブロックされます。「失敗校のみ再読取」で全校成功させてください。
  2. Preflight 実行後に設定を変更しませんでしたか？ → Profile Editor で設定を変えるとハッシュ不一致となり、再Preflightが必須となります。
  3. 有効期限（24時間）が切れていませんか？ → 期限切れの場合は再度 Preflight を実行してください。

Q2. 一部の学校が「破壊的変更スキップ」されました。どうすればよいですか？

本ツールの自動適用では、予約投稿消去リスクのある学校は安全のため自動的にスキップされます。
これらを適用したい場合は、教育委員会や各学校現場と事前に調整のうえ、手動で管理画面から変更するか、運用責任者による承認のもと CLI から専用オプションを指定して適用します。

Q3. CSVアップロード時に「ヘッダーが不正です」等のエラーが出ます。

CSVの1行目が schoolCode,schoolName,userId,password,enabled になっているか確認してください。
また、Excel で保存する際に「CSV UTF-8（コンマ区切り）」を選択したかご確認ください。

9. ステータスコード・エラー用語早見表

コード名 分類 意味とオペレーターが取るべき対応
SUCCESS 正常完了 設定変更・保存・検証がすべて正常に完了しました。
SUCCESS_ALREADY_CONFIGURED 正常完了 現在値が目標設定とすでに一致していたため、書き込みをスキップして完了しました。
SKIPPED_DESTRUCTIVE 安全スキップ 予約投稿削除リスクがあるため、本番適用から自動除外されました（事故防止）。
PREFLIGHT_STATE_CHANGED 安全スキップ Preflight 実施後に学校管理者が手動で設定を変更した形跡を検知したため、上書き防止でスキップしました。
SAVE_OUTCOME_UNKNOWN 重大エラー 保存ボタン押下後に通信が遮断され、成否が判定できません。二重事故防止のため即時停止しました。手動で画面確認を行ってください。
INTERRUPTED 安全中断 「安全に停止」ボタンによる意図的な中断です。「Preflight を再開」で続きを実行可能です。
LOGIN_FAILED エラー ログインに失敗しました。CSVの userId または password を確認してください。
CONTRACT_NOT_AVAILABLE 警告 その学校で未契約の機能です。設定項目を UNMANAGED に戻すことを推奨します。
